# AutoSci Cytoscape Graph Visualization — Design

Date: 2026-06-22
Status: Approved (brainstorming) — pending implementation plan

## Goal

Replace the dashboard's hand-rolled SVG graph renderer (`apps/desktop/src/renderer/components/GraphVisualization.tsx`)
with a port of the upstream AutoSci / ΩmegaWiki visualization (`AutoSci/app/modules/graph.js`):
Cytoscape.js canvas + the `obsidianForceLayout` force-directed layout + the full interaction set
(entity/edge styling, zoom-aware labels, search, entity filters, grouped/collapsible edge filters,
preset views, BFS highlight, two-node path query, low-confidence toggle, edge hover tooltips).

The new renderer is **shared**: it draws every graph the dashboard produces, including graphs NOT
generated by AutoSci (the project-docs harness *provenance* graph), not only paper/AutoSci graphs.

## Decisions (from brainstorming)

- **Engine:** Cytoscape.js, added as an npm dependency of `@apc/desktop` (NOT the AutoSci CDN ESM import —
  the app is offline Electron with a CSP; a bundled dep is required).
- **Scope:** all graphs. One Cytoscape renderer replaces the SVG renderer everywhere. The old SVG
  `layoutGraph` + SVG rendering are removed.
- **Data source:** the dashboard's existing IPC data, unchanged at the transport layer —
  `buildPaperGraphData` (paper) and `buildHarnessGraphData` (project-docs) → `HarnessGraphData`. We do NOT
  depend on AutoSci's `tools/serve.py` `/api/graph` server.
- **Feature scope:** the full graph.js interaction set in v1 (not a subset).

## Non-Goals

- Aligning the dashboard's domain schema to AutoSci's entity/edge vocabulary (papers/concepts/topics/
  people/ideas/experiments/methods/foundations). Our vendored paper pack uses papers/modules/pipelines/
  pipeline_trials; that divergence stays. The renderer is vocabulary-agnostic.
- Consuming AutoSci's `citations.jsonl` or frontmatter-projected edges (the dashboard does not produce
  them). Styling that depends on those fields degrades gracefully when absent.
- Running AutoSci's Python server.

## Architecture

### Components and modules

| Unit | Kind | Responsibility |
|------|------|----------------|
| `components/GraphVisualization.tsx` | React | Cytoscape lifecycle (init/destroy), canvas mount, wiring sidebar widgets to the cy instance, mapping `HarnessGraphData` → cy elements. Keeps props `{ data: HarnessGraphData; onNodeClick }`. |
| `graph/graph-layout.ts` | pure | `obsidianForceLayout(nodes, edges, width, height) → { positions, sizes }`. Ported from graph.js L242. |
| `graph/graph-algorithms.ts` | pure | `bfsNeighborhood(adj, startId, depth)` and `findPaths(adj, startId, endId, maxDepth, maxPaths)`. Ported from graph.js L524 / L872. |
| `graph/graph-style.ts` | pure-ish | Entity colors, edge `type → workflow → color`, edge category groups, preset → category map, `directionFor`, `confidenceClass`. Covers BOTH our schemas. `presentEntityTypes`/`presentEdgeTypes` derive from data. |

Cytoscape and DOM-bound interaction code live in the component; the testable graph math/style/algorithm
logic lives in the three pure modules.

### Data enrichment

`HarnessGraphLink` gains optional fields so AutoSci-style edge rendering has something to key on:

```ts
type HarnessGraphLink = {
  id: string; source: string; target: string; label?: string; kind: string;
  confidence?: 'high' | 'medium' | 'low';   // NEW — drives opacity/width weighting
  direction?: 'directed' | 'symmetric';     // NEW — drives arrowhead
  workflow?: string;                          // NEW — drives workflow color group + filter grouping
}
```

- `buildPaperGraphData`: carry `confidence` as a structured field (today it is concatenated into the
  label string `type · conf` — that string concat is removed); map each paper edge `type` to a workflow
  group + direction via `graph-style`.
- `buildHarnessGraphData`: derive `direction`/`workflow` from existing `kind` where sensible (provenance
  edges are directional). No behavior change to which nodes/edges are produced.

### Styling config (`graph-style.ts`)

- **Entity colors:** a table covering project-docs types (`run/task/evidence/file/document`) AND paper
  entities (`papers/modules/pipelines/pipeline_trials`). Unknown types fall back to a neutral gray.
- **Edge workflow groups + colors:** map each known edge type/kind to a workflow bucket and color;
  unknown types collect under "Other" (mirrors graph.js leftover handling, no silent drops).
- **Presets:** preset → list of workflow/category groups; only presets with present edge types render.
- **Direction / confidence:** `directionFor(type)` defaults directed; `confidenceClass(conf)` →
  `conf-high|medium|low` weighting.

### Interactions (component, mirrors graph.js)

Left-click node = BFS highlight (depth from sidebar); right-click = set path start/end → highlight paths;
double-click = `onNodeClick(node)` (opens the existing peek drawer); edge hover = tooltip
(source/field/confidence/evidence when present); zoom = re-evaluate label visibility (hidden below a zoom
threshold unless "always show labels"). Sidebar: search (centers + BFS on a hit), entity filters,
grouped/collapsible edge filters with per-type + per-group toggles, preset buttons, low-confidence toggle,
node info panel, stats line.

## Data flow

`KnowledgeView` builds `HarnessGraphData` (paper or project-docs) → passes to `GraphVisualization` →
component maps nodes/links to cy elements, runs `obsidianForceLayout` for `preset` positions, applies the
`graph-style` stylesheet, and binds interaction handlers. Selection/peek still flows through
`onNodeClick`.

## Testing strategy

- **TDD (pure modules):** `graph-layout` (deterministic positions: seedless determinism via fixed
  pseudo-random or accept jitter and assert invariants like "connected nodes end closer than the canvas
  diagonal", node count preserved, within-bounds), `graph-algorithms` (BFS depth correctness, path
  finding hits/misses/cap), `graph-style` (type→color, type→workflow, present-types derivation, Other
  bucket, confidence class).
- **Data builders:** extend existing `harness-utils` tests for the new structured `confidence`/`direction`/
  `workflow` fields on links.
- **Component:** mount smoke test + verify it maps the right element counts; Cytoscape's canvas rendering
  is out of scope for jsdom. The existing `GraphVisualization.test.tsx` (SVG-specific) is replaced.

## Risks / impact

- `app.css`: add graph shell + sidebar styles (dark palette, our CSS variables).
- The shared swap means the project-docs provenance graph also renders via Cytoscape; its edge kinds map
  to "Other" workflow groups and entity colors come from the project-docs side of the table.
- `cytoscape` adds renderer-process bundle weight; acceptable for a desktop app.
- Determinism: graph.js seeds initial positions with `Math.random()`. For testability and stable layouts
  across renders we will seed deterministically (e.g. index-based angle, no RNG) — a deliberate deviation
  from graph.js noted here.

## Out-of-scope follow-ups

- Adopting AutoSci's full entity/edge schema + `config/visualize.json` verbatim.
- Merging `citations.jsonl` as a second edge source.
- Persisting per-graph layout positions.
